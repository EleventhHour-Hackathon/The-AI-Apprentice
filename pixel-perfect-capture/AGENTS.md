## Voice architecture
- The voice agent is an ElevenLabs agent (ElevenAgents). Its prompt, voice, turn-taking and client tools are defined in `core/backend/src/services/apprentice_agent.py`; run `uv run python -m src.services.apprentice_agent` there after changing it. Never edit the agent in the ElevenLabs dashboard, the next sync overwrites it. `scripts/rehearse_agent.py` replays a scripted session over text to check its behaviour.
- `use-apprentice` owns the ElevenLabs conversation (`@elevenlabs/client`, WebRTC with a token from `/api/v1/agent/token`), the client tools and the session record. Keep voice transport there.
- When to speak is decided in the pill, not by the agent: `lib/floor.ts` (tested) reads talking (VAD), typing/scrolling (screen pixel activity) and reading (a document just opened), and sends `[PAUSE]` only at a natural pause after an on-screen action (or, before the first three questions, a document they opened). The apprentice asks at least three live questions, one about a guardrail, with no upper limit; the `[PAUSE]` message carries the count. Only a reply to a `[PAUSE]` that is a question counts, and not once the expert puts it off with Later; each is labelled guardrail / reason / other by `/sessions/{id}/live_question` (`core/backend/src/services/live_questions.py`), which is what "one about a guardrail" checks. If End is pressed before the minimum is met, the pill runs a wrap-up (`decideWrapUp` in `lib/floor.ts`) that asks the missing questions before `[TASK DONE]`; End again skips it. Replies the agent makes without the floor are muted and it is told `[NOT HEARD]`.
- `use-screen-events` runs a fast local activity check and a slower vision call (`/api/v1/screen_event`); changes reach the agent as silent `[SCREEN mm:ss]` context updates and are stored with a thumbnail as screen moments.
- Show an answer as captured only after the agent calls a recording tool, never on a timer.
- After the teach-back is confirmed the call stays open for a REVIEW: the expert can change, remove or add a step or rule by voice (`edit_work_map`, `read_work_map` client tools → `/sessions/{id}/edit` and `/summary`, `core/backend/src/services/work_map_edit.py`). Edits are saved over the map and kept as corrections so a later merge keeps them; the agent only hangs up once the expert says they are done. `scripts/rehearse_agent.py --review` replays this over text.
- Work Maps are merged by `core/backend/src/services/work_map_merge.py` from screen events, transcript and live captures: a draft at `start_debrief` (its gaps drive the debrief) and the final map at `confirm_work_map`. Quotes must appear in what the expert said and times are snapped to screen events; keep it that way. `core/backend/src/services/work_map_links.py` decides the links: forgiving quote matching that keeps the transcript's own words, "said while doing it" (`quote_kind: narration`, never taught as a reason) for steps without a reason, guardrail moments from when it was said or its step (`at_source`), and moments for items added by voice. Anything still without a moment or the expert's words is shown as Unlinked.
- Supabase holds sessions (`work_maps`), screen moments (`screen_events`, with thumbnails), recordings and clips (`screen_recordings`, `screen_clips`; the video is in the private `screen-recordings` Storage bucket, read with `SUPABASE_SECRET_KEY` and served as signed URLs) and lessons; only the backend touches them (RLS on, no policies). The backend's `uploads/media/` is just a cache of the bucket plus uploads still waiting to go up. Deleting a Work Map removes its video too; sessions that end with nothing said are discarded. `core/backend/scripts/sync.py` re-aligns disk, Storage and the database (`--dry-run` to report). Schema changes go in `core/backend/storage/migrations/`.
- Work Maps (`/work-maps`) draw with React Flow in `WorkMap.tsx`: steps on a timeline with their screen moment, guardrails under the step they belong to. Do not draw links the merge did not record.
- What the apprentice already knows carries between sessions (`core/backend/src/services/brain.py`). Memory is the confirmed Work Maps only, never drafts. It is read at connect (`/api/v1/brain`, the tasks it has learned, as the `known` dynamic variable) and again when the task is named (`begin_observation` waits for `/sessions/{id}/task`, which hands back a `[KNOWN]` block for that task), and it is written back by the final merge, which is given what was known so it extends that map rather than replacing it. A matching task is one whose words overlap an earlier task's; at this size the brain is a prompt, not a retrieval system. Every read degrades to "knows nothing" if the store is unreachable, so a session never fails because memory is down.
- Teaching (Module 3): the tutor is a second ElevenLabs agent ("AI Apprentice Tutor", same file as the apprentice) that gets the Work Map as the `work_map` dynamic variable. `use-tutor` + `Tutor.tsx` run a lesson in the pill (desktop: `lesson:<work map id>` pill command; browser: `/?lesson=<id>`). Every screen event is checked by `/api/v1/lessons/{id}/check` (`core/backend/src/services/tutor.py`), which applies the expert's rules to the new case; `intervene` sends `[STOP]` at once (stepping in is the point here), predictions and explanations wait for a pause. The report (mastered / practice next / not covered) is computed from recorded attempts, not by an LLM. `scripts/rehearse_tutor.py <work map id>` replays a lesson over text.
- Privacy: nothing raw leaves the machine. `use-privacy-shield` reads the screen locally (tesseract.js), paints over personal data found by `lib/pii.ts` (tested) and hands out only the shielded copy; screen events, thumbnails, recordings and the tutor's view all use it, and it fails closed (no shield, no sharing). The backend redacts text the same way (`core/backend/src/services/privacy.py`) on transcripts, captures, questions, edits and lesson data. Unconfirmed Work Maps are deleted after 30 days (`purge_unconfirmed` in `core/backend/main.py`). Don't add a path that sends the raw stream anywhere.
- Demo: `/sandbox` is Ledgerly, a practice ERP with the challenge's invoices (`lib/sandbox.ts`; `?set=newhire` for the tutor's unseen case). It must not enforce the expert's rules; those are what the apprentice learns. Run sheet and pitch: `docs/DEMO.md`, `docs/PITCH.md`.
- Languages: the apprentice and the tutor speak any of the 72 ElevenLabs agent languages (`lib/languages.ts`, `core/backend/src/services/languages.py`; keep them in sync). The expert picks one in the pill (or Auto-detect), the new hire another next to "Teach a new hire"; it is sent as `overrides.agent.language`. Each language has a preset with a translated first message (`agent_first_messages.json`, translated once at sync). The Work Map is always written in English; quotes stay exactly as said, with `quote_translation`/`quote_language`. Don't translate quotes in place.
