Plan:
1. `follow_ups.py`, pure helpers (no I/O), with docstrings in the file's style:
   - `parent_of(captures) -> Optional[str]`: the `work_map_id` of the first dict capture with `kind == PARENT` and a str `work_map_id`, else None.
   - `_key(text)`: lowercased, whitespace collapsed, stripped (same idea as `work_map_merge._dedupe`, which you must not import from: keep it local).
   - `lead_with(pending, open_questions) -> List[str]`: the pending texts first (in pending order), then the draft's own open questions, dropping blanks and repeats by `_key` (first wins). `pending` is the list `pending()` returns.
   - `delivered(pending, asked, session_id, now) -> List[dict]`: one `closed(q["question_id"], DELIVERED, now, session=session_id)` per pending question whose `_key(text)` is among the `_key`s of `asked` (the session's saved draft open questions); none otherwise.
2. `start_session(session_id, payload)`: keep the current behaviour when `parent_work_map_id` is absent, None or "". When present: `parent = _uuid(value, "Work Map")` (404 "Work Map not found" for a non-UUID); `parent == session_id` → 422 "A session can't be recorded again from itself"; `work_map_store.get(parent)` is None or has `status == "recording"` → 404 "Work Map not found". Then `start_session` as today, then `get(session_id)` and, only if `follow_ups.parent_of(row["captures"])` is None, `add_capture(session_id, {"kind": follow_ups.PARENT, "work_map_id": parent})`. The pill calls start twice with the same parent: the second call must not add a second capture. A different parent on the second call is ignored (first wins). Store exceptions → `_store_unavailable` (503) as today. The parent id is a canonical UUID, nothing to redact.
3. `merge_session`, when `parent_id = follow_ups.parent_of(session.get("captures") or [])` is set: read the parent once with `work_map_store.get(parent_id)` right after the session read; if it raises or returns None, `logger.warning(...)` and continue as if there were no parent (the session must still merge and save). `pending = [ {**q, "text": redact(q["text"])} for q in follow_ups.pending(parent["captures"] or []) ]` (redact again because these go to ElevenLabs and back to the UI, even though B-37 redacted them on the way in).
   - Draft merge (`final` false): after `work_map.update(...)` and before `save_map`, set `work_map["open_questions"] = follow_ups.lead_with(pending, work_map["open_questions"])`. The saved draft, the response's `open_questions` (which the pill keeps as `gaps`) and `brief_for_agent(work_map)` then all lead with them. A second draft merge (`saveDraft` at the end of an unconfirmed session) does the same, deduped, so nothing doubles.
   - Final merge (`final` true): do NOT add them to the final map's `open_questions`. Only after `save_map` succeeded, append each capture from `follow_ups.delivered(pending, session.get("open_questions") or [], session_id, datetime.now(timezone.utc))` to the parent with `work_map_store.add_capture(parent_id, c)`. Because `pending` excludes already delivered or withdrawn questions, a retried final merge delivers nothing twice; a question added to the parent after the debrief's draft was saved is not in the draft's `open_questions`, so it stays pending. A failure while appending is logged and does not fail the response (the map is already saved). A session that ends unconfirmed delivers nothing (its questions stay pending for the next "Record again"; carrying them forward is B-53).
   - A session without a parent capture must behave exactly as today (same calls to the store, same response).
