## M-02 · The always-on apprentice: a deterministic coverage check (first slice) · implementer-3 · in progress
Base: ddec0e5 (`git rev-parse --short HEAD` in your worktree must match). Repo /Users/mithra/.builds/sia (you work in your own worktree of it). Gate: `/Users/mithra/.builds/sia/.claude/check.sh ddec0e5` must print ALL CHECKS PASSED.
Goal: given one screen event ("Opened invoice from Bauer Hydraulik: hydraulic press, coded to 4711"), the backend says whether any confirmed Work Map already covers it (which map, which step or rule, how sure). If none does, it gives back one short question to ask the expert ("I haven't seen ... before. How do you handle it?"). Deterministic, no LLM. Nothing calls it live yet: the novel-case inbox is B-11, and stopping the autopilot at uncovered cases is B-56.
Brief says: Moonshot, "The always-on apprentice. No scheduled sessions. It notices a case it has never seen during everyday work and asks one question at the right moment." (docs/CHALLENGE.md, Stretch goals list).

Background (core/backend, read only):
- Work Map shape (what `storage/work_maps.get(id)` returns): `{"id", "task", "status": "recording"|"draft"|"confirmed", "steps": [{"id", "title", "screen", "decision", "reason", "judgment", ...}], "guardrails": [{"id", "rule", "kind", "applies_when", "ask_whom", "step", ...}], ...}`. Since M-01, items may carry `"removed": True` (flagged as no longer done); such items do not count as coverage. `storage/work_maps.list_summaries()` returns `[{"id", "task", "confirmed", "status", ...}]` without contents.
- Screen events look like `{"t", "event", "description", "kind"}`; `event` is a one-line English description already redacted by `/screen_event` (`src/router/path_router.py:53-100`).
- `src/services/work_map_diff.py`: `similarity(a, b)` (line 103), the shared Dice word-overlap helper (numbers and stopwords ignored, 0..1). Reuse it, don't write another. Read its threshold comments (`STEP_MATCH` etc.): calibrate yours the same way and write the measured scores in a comment.
- `src/services/diff_questions.py`: `trim(text, limit)` (public) cuts at a word boundary. Quote labels like `work_map_links._label` does (`'text'`), but don't import underscore names from other modules (B-55 will add a test that forbids it); write the two-line quoting inline.
- `src/services/privacy.py`: `redact(text)`.
- Router pattern and tests: `src/router/follow_ups_router.py` (`_uuid`, `_store_unavailable` imported from path_router) and `tests/test_follow_ups.py` / `tests/test_next_session.py` (TestClient on a bare `FastAPI()` app, store functions monkeypatched).

Owns: core/backend/src/services/coverage.py (new), core/backend/src/router/coverage_router.py (new; exposes `router`), core/backend/tests/test_coverage.py (new).

Plan:
1. `coverage.py`, pure (no I/O, no LLM, inputs not mutated), with a module docstring like `work_map_diff.py`'s (what counts as covered, why deterministic, what comes later).
   - Item text: a step = `title`, `screen`, `decision` joined; a guardrail = `rule`, `applies_when` joined. Skip items with `removed: True`. Missing ids → `s<n>`/`g<n>` by position (1-based), like the diff does.
   - Score every item of every map with `similarity(event_text, item_text)`. Best = highest score; ties → earlier map in the input order, then steps before guardrails, then item order.
   - `COVERED = <calibrated>` (start near 0.3). Write 6-10 realistic hand events against two hand-written maps (an invoice-coding map and an unrelated one, e.g. a travel-expense or KYC map), measure, set the constant so that events matching a step or rule are covered and different cases (a new supplier type, a credit note, a currency the maps never mention) are novel. Record the measured scores in the comment above the constant.
   - `MIN_WORDS = 2`: an event with fewer content words than that (empty, "Scrolled", "Idle") is `{"verdict": "ignored"}`. Use the same word notion `similarity` uses, via its public helpers or by checking `similarity(t, t) == 0`. No underscore imports.
   - `NOVEL_QUESTION = "I haven't seen {label} before. How do you handle it?"` with `label` = the redacted event trimmed to `MAX_LABEL = 80` chars and quoted `'...'`.
   - `check(event_text: str, maps: list[dict]) -> dict` returns one of:
     `{"verdict": "covered", "work_map_id", "task", "section": "steps"|"guardrails", "item_id", "title", "score"}` (title = step title or rule),
     `{"verdict": "novel", "question": str, "best": <the same fields as covered, without verdict> | None}` (best is None when no map has any item),
     `{"verdict": "ignored"}`.
     Score rounded to 3 places. `work_map_id`/`task` come from the map dict (`id`, `task`, "" if missing).
2. `coverage_router.py`: `router = APIRouter(prefix="/api/v1", tags=["Coverage"])`; plain `def` endpoint `POST /coverage/check`, Pydantic body `{"event": str (1..500 chars), "work_map_ids": list[str] | None (max 50)}`. Redact the event (`privacy.redact`) before anything else. Maps: `list_summaries()`, keep `status == "confirmed"` (and, if `work_map_ids` is given, only those, each checked with `_uuid(id, "Work Map")`), then `get(id)` each (skip a None: deleted meanwhile). Store errors → `_store_unavailable` (503). Response: the `check` result plus `"maps_checked": n`. A blank event after stripping → 422 "An event needs its text". No confirmed maps → `novel` with `best: None`, `maps_checked: 0`.
   Comment the cost: one `get` per confirmed map per call; fine for a demo, a cached index comes with B-11.
3. `tests/test_coverage.py`: the calibration events as a table-driven test (each expected covered/novel with the expected map and item); ties and ordering; `removed` items ignored; items without ids; empty maps list; ignored events; the question is redacted (an event with an IBAN or e-mail gives a question without it) and trimmed; endpoint: 200 covered, 200 novel, only confirmed maps are read (a draft map that would match is not), `work_map_ids` filter, bad id → 404, blank event → 422, store error → 503, `maps_checked` count.

Done when: `cd core/backend && uv run --extra dev pytest -q tests/test_coverage.py` passes and the whole suite still passes (only the known privacy-extra skip); `uvx ruff check` and `uvx ruff format --check` clean on the three new files; `/Users/mithra/.builds/sia/.claude/check.sh ddec0e5` prints ALL CHECKS PASSED. In the report: the calibration table (event, best item, score, verdict) and the value chosen for `COVERED`. The endpoint can't be reached in the app until the Integration commit registers the router; don't edit main.py.

Contract (for B-11 and B-56 later): `POST /api/v1/coverage/check` body `{"event": "<text>", "work_map_ids": ["<uuid>", ...] (optional)}` → 200 `{"verdict": "covered", "work_map_id", "task", "section", "item_id", "title", "score", "maps_checked"}` | `{"verdict": "novel", "question", "best": {...} | null, "maps_checked"}` | `{"verdict": "ignored", "maps_checked"}`; 404 bad id, 422 blank event, 503 storage.
